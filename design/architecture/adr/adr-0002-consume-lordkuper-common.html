ADR-0002 · Consume LordKuper.Common over local reimplementation

accepted · subsystem N/A · updated 2026-06-07
accepted subsystem: N/A ADR-0002

Context

The reuse audit (RU-1…RU-8) found that several EquipmentManager types are near-verbatim reimplementations of utilities the upstream LordKuper.Common library now ships. This violates the concept anti-pillar "not a reimplementation of shared utilities" and custom-common-rules.md ("do not fork or reimplement what it already provides"). Crucially, the Common equivalents already contain fixes for EM defects, and deleting the EM copies removes code that would otherwise need the nullable migration. The overlaps were verified against the Common source at ..\..\rimworld-common (treated as untrusted first-party data):

  • RU-1: WorkTypeRule (290 lines) ≈ Common.WorkTypeThingRule + WorkTypeStatMap — same public surface, same AllRelevantThings predicate, same DefaultWorkTypeStats literal (RU-5). The audit recorded a save-format break: EM serializes List<StatWeight> under key "StatWeights"; WorkTypeThingRule serializes Dictionary<string, StatWeight> under nameof(StatWeights) with LookMode.Value (confirmed in WorkTypeThingRule.cs:146-159).
  • RU-2: EquipmentManagerGameComponent_StatRanges (_statRanges + NormalizeStatValue + UpdateStatRange) ≈ Common.StatRanges. Both held the identical first-sample seeding defect (C-4). The blocker (Common's StatRanges was internal) is resolved: rimworld-common commit 17199b6 made it public static, fixed C-4, added Clear(), and shipped 11 green tests (verified in upstream source: StatRanges.cs:24 public static class, :38 Clear(), :64 NormalizeStatValue).
  • RU-3: ItemCache ≈ Common.ThingCache (the StatValues dictionary + timed clear). Confirmed ThingCache.cs:13 public class.
  • RU-4: EquipmentManagerStatDefs is a pure pass-through over Common.Helpers.StatHelper.GetStatsByCategory.
  • RU-6: UiHelpers.GetWindowSize duplicates Common.UI.Windows.GetWindowSize (confirmed Windows.cs:22).
  • RU-7: the hand-rolled work-type editor tab overlaps Common.UI.Widgets.WorkTypeThingRuleWidget (takes WorkTypeThingRule, so gated on RU-1).

Backward-compat policy is backward_compat=none, and RU-1's breaking save-format change was explicitly approved (audit decision 2026-06-07): no save-migration shim; old saves silently drop persisted WorkType rules and users rebuild via defaults. RU-2 was also approved, accepting that stat ranges become process-global ephemeral (no longer save-persisted).

Decision

Delete the EM code that duplicates Common's public surface and consume Common instead. Specifically: delete WorkTypeRule and consume WorkTypeThingRule/WorkTypeStatMap with no Scribe save-migration shim (RU-1 / RU-5 / RU-7); delete EquipmentManagerGameComponent_StatRanges, the _statRanges dict, ExposeData_StatRanges, and LegacyCustomStatDefs.NormalizeStatRanges, and consume the now-public, defect-fixed Common.StatRanges (RU-2); re-base the weapon/tool caches on Common.ThingCache and delete ItemCache (RU-3); delete EquipmentManagerStatDefs and inline StatHelper.GetStatsByCategory(StatCategory.X) at its five call-sites (RU-4); delete UiHelpers.GetWindowSize and call Common.UI.Windows.GetWindowSize (RU-6); adopt WorkTypeThingRuleWidget bundled with RU-1, or defer it with rationale (RU-7).

Sequencing (load-bearing, AC-1): all of the above land and build green before the ADR-0001 nullable flip, so deleted code is never annotated. WorkTypeRule.cs alone removes the 36-site nullable hotspot.

Auto-resolutions: RU-1 deletes the four redundant double-guards (C-9) and the duplicated DefaultWorkTypeStats literal (RU-5); RU-2 brings the upstream C-4 fix. The DefProvider testability seam (RU-8) comes along for free once the duplicated types move to Common, easing the test workstream (C-18…C-21).

Kept local — explicitly NOT migrated (verified to have no Common equivalent or to be legitimate EM-side adaptation; AC-33):

TypeWhy kept
SkillWeight, PawnCapacityWeightSingle-float weights; Common offers limits (min/max ranges) which EM already consumes in Loadout. Different concept, no Common analog.
PassionLimitA PassionValue enum gate; no Common equivalent.
RangedWeaponCache / MeleeWeaponCache / ToolCache scoringEM-specific CE-aware verb/range banding + ammo + work-type stat logic; Common has no weapon-scoring cache. (Caches re-base on ThingCache per RU-3 but the scoring stays EM-local.)
CombatExtendedHelperEM-specific optional-dep reflective binding (see ADR-0003). Common has no CE compatibility layer.
LegacyCustomStatDefs (remainder, after NormalizeStatRanges is removed)EM-side normalization of legacy EM_ stat names onto Common's current CustomStats naming — adaptation of Common, not reimplementation (C-23 PASS).
Logger wrapperThin wrapper injecting EquipmentManagerMod.ModId into Common.Logger — the intended consumption pattern (Common's Logger takes a modId param so each downstream mod wraps it). Keep; it makes C-16 the correct fix.
UiHelpers remainder (CycleSettingValue, GetSettingCheckboxState, ValidNameRegex, gap/label helpers)EM-specific; only GetWindowSize is a duplicate. A fuller UiHelpers→Common.UI migration is a separate behavior-sensitive UI pass, out of scope.

Consequences

Positive

  • Restores the "not a reimplementation of shared utilities" anti-pillar; one source of truth for work-type rules, stat ranges, the thing cache, stat-category lookups, and window sizing.
  • Shrinks the nullable-migration surface before the flip (≈36 distinct sites from WorkTypeRule alone, plus the wrapper files).
  • Inherits the upstream C-4 fix (RU-2) and erases C-9 / RU-5 by deletion rather than by patching.
  • Brings the DefProvider test seam into EM's stat/rule paths, unblocking the test workstream.

Negative

  • Breaking save-format change (RU-1): existing saves silently lose customized work-type rules; no migration shim. Accepted under backward_compat=none; users rebuild from defaults.
  • Stat ranges become process-global ephemeral (RU-2): no longer save-persisted; rebuilt each process via InitializeStatRanges. A first-tick scoring pass may run against a not-yet-fully-seeded range until samples accumulate — behaviorally equivalent to a fresh load, accepted.
  • Possible scoring drift if EM's flat 2f default work-type stat weight differs from Common's per-stat weighted DefaultWorkTypeStats; this changes assignment decisions. Characterized by tests before/after (ADR-0004, AC-26).
  • Tighter coupling to the Common version: RU-2 requires the Common build at or past commit 17199b6. EM already builds against the rebuilt 1.6 dll (2026-06-07).
  • RU-7 (widget adoption) carries UI pixel-parity risk; may be deferred (AC-7).

Alternatives considered

  • Add a Scribe load-migration shim for RU-1 (read the legacy list form, populate the dict) — rejected: backward_compat=none makes it unnecessary churn; the approved decision is to drop old persisted rules.
  • Keep EM's StatRanges copy and fix C-4 locally — rejected: the upstream fix already shipped and was verified; keeping a local copy re-introduces the very duplication this ADR removes and risks the two copies drifting again.
  • Defer RU-1 and take only the non-breaking wins (RU-3/RU-4/RU-6) — rejected: RU-1 was approved, and deferring it leaves the largest nullable hotspot in place and the anti-pillar partly violated.
  • Migrate UiHelpers wholesale to Common.UI — rejected for this sprint: behavior-sensitive layout refactor with pixel-parity risk; only the exact GetWindowSize duplicate is removed.
  • Delete the kept-local weight/limit/passion types in favor of Common limits — rejected: they are a different concept (weights/enum gate vs min-max limits); not duplicates (AC-33).
